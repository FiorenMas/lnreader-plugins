```bash

```

## Plugin anatomy

One plugin is one **folder**, not a single file:

```
plugins/<language>/<PluginName>/
├── index.ts          # entry point, default-exports a plugin instance
├── utils.ts          # optional: split code across as many files as you like
├── icon.<ext>         # optional: local icon; basename matches metadata.icon
└── webview/
    ├── style.css      # optional: source of customCSS, copied byte-for-byte
    └── index.ts       # optional: source of customJS, bundled separately
```

- `<language>` must match a key in `scripts/languages.js`, lowercased on disk
  (`vietnamese`, `english`, `japanese`, `korean`, `multi`, …).
- `<PluginName>` is PascalCase without spaces.
- `index.ts` must `export default new YourPlugin()` — an **instance**, not the class.
- Rename the folder to `broken_<PluginName>` to exclude it from the dev registry,
  plugin build, webview build, type checks, and manifest. No marker file is used.
- There is no registration step and no `plugins/index.ts`. The dev UI discovers
  plugins with `import.meta.glob` over `plugins/*/*/index.ts`.

### Icons and assets

Source assets live beside the plugin. The icon filename is the basename in the
`icon` metadata field, CSS is `webview/style.css`, and Custom JS is
`webview/index.ts` or `webview/index.js`:

```ts
icon = 'icon.png';
customCSS = 'style.css';
customJS = 'player.js';
```

Short filenames are normalized to `src/<plugin.id>/<filename>` and emitted
under `public/static/`. A metadata value containing `/` preserves its legacy
full path. This plugin ID namespace means new plugins do not need a language
prefix or folder path in asset metadata. Run `npm run build:assets` to copy
icons and CSS byte-for-byte and bundle Custom JS to the normalized paths.
`npm run build:webviews` is a compatibility alias. Missing declared local
assets or duplicate destinations fail the build. CSS files are copied as
standalone files; relative resources they reference are not copied
automatically. There is no watch mode, so rerun the asset build after edits and
rebuild plugin bundles when metadata changes. Because the emitted path changes
when migrating to a short filename, bump the plugin patch version.

Language segments in the asset path are short codes (`vi`, `en`, `jp`, `kr`,
`multi`). Icons should be 96x96 px. Generated files under `public/static/` are
build output and are not plugin source files. In particular,
`public/static/src/` is generated output; fallback images directly under
`public/static/` remain source files. The icon downloader fills only missing
local icons, preserves existing icons and fallback files, and does not delete
unrelated static files.

## Plugin types

Import the abstract class from `@nekori/plugin` and use `extends`:

| Class | Use when |
| --- | --- |
| `NekoriBasePlugin` | `parseNovel` returns the complete chapter list, including volume-grouped novels. |
| `NekoriPagePlugin` | Paginated chapters: `parseNovel` returns positive integer `totalPages` and `parsePage` loads a page. |

Volumes use `ChapterItem.page` as a label (for example `'Volume 1'`) on a base plugin.
Paged plugins use canonical positive integer strings such as `'1'`, `'2'`, not volume labels.
`Plugin.PluginBase` and `Plugin.PagePlugin` are legacy LNReader interfaces: `parseChapter(): Promise<string>`.
Nekori plugins return `Promise<Plugin.ChapterContent>`. The linked templates contain complete classes.

## Metadata fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | `string` | yes | Unique across all plugins. Must be a valid filename — the manifest build throws otherwise. |
| `name` | `string` | yes | Display name. |
| `icon` | `string` | yes | Local basename, e.g. `icon.png`; auto-namespaced under `src/<id>/`. Legacy paths with `/` are preserved. |
| `site` | `string` | yes | Site URL. Also the URL opened in the WebView and the base URL of the reader. |
| `version` | `string` | yes | [SemVer 2.0](https://semver.org/). **Bump it or the publish pipeline skips your changes** (`--only-new` compares versions). |
| `isNekoriPlugin` | `true` | inherited | Base class flag selecting the chapter contract. |
| `minApiVersion` | `number` | inherited | Required host API version. |
| `outputTarget` | `'js' / 'hermes' / 'all'` | no | No-op: all values currently build JS only, not HBC. |
| `filters` | `Filters` | no | See [Filters](#filters). |
| `pluginSettings` | `Plugin.PluginSettings` | no | See [Plugin settings](#plugin-settings-and-storage). |
| `imageRequestInit` | `Plugin.ImageRequestInit` | no | Extra `method` / `headers` / `body` for image requests, when a site blocks hotlinking. |
| `customCSS` | `string` | no | Path relative to `public/static/`. |
| `customJS` | `string` | no | Path relative to `public/static/`; built from `webview/`. |
| `contentType` | `ContentType` | no | `NOVEL`, `IMAGE`, `VIDEO`, `MIXED`. **Nekori only** |
| `contentWarning` | `ContentWarning` | no | `UNSPECIFIED`, `SAFE`, `MIXED`, `NSFW`. **Nekori only** |
| `webStorageUtilized` | `boolean` | no | Set when the plugin needs the reader WebView's `localStorage` / `sessionStorage` (e.g. a session kept in web storage instead of cookies). |

Bump the plugin version when publishing changes. The API version is controlled centrally in `src/nekori/plugin.ts`.

```ts
import { NekoriBasePlugin } from '@nekori/plugin';
import { ContentType, ContentWarning } from '@nekori/pluginMetadata';

// Metadata excerpt; implement abstract methods as in the templates.
class MyPlugin extends NekoriBasePlugin {
  id = 'myplugin.id';
  name = 'My Plugin';
  icon = 'icon.png';
  site = 'https://example.com';
  version = '1.0.0';
  contentType = ContentType.NOVEL;
  contentWarning = ContentWarning.SAFE;
}
```

### Repository manifest

The manifest remains a JSON array. The build reads metadata from the exported index.ts instance
using mocked runtime APIs; there is no second hand-written metadata file. Language comes from
the directory via scripts/languages.js; JS/icon/CSS/customJS URLs are generated from build configuration and asset paths.
The app validates minApiVersion when present (positive integer), rejecting installation/loading above its supported API.
Loaded code metadata determines the contract; bump the plugin version so the app offers the update.

Example entry (illustrative URLs):

```json
[
  {
    "id": "example",
    "name": "Example",
    "site": "https://example.com",
    "lang": "English",
    "version": "1.0.0",
    "url": "https://repo.example/plugins/english/Example.js",
    "iconUrl": "https://repo.example/static/src/example/icon.png",
    "contentWarning": 0,
    "contentType": "novel",
    "isNekoriPlugin": true,
    "minApiVersion": 1
  }
]
```

## Methods

### popularNovels

```ts
popularNovels(
  pageNo: number,
  options: Plugin.PopularNovelsOptions<typeof this.filters>,
): Promise<Plugin.NovelItem[]>
```

Called for the plugin's front page. `options.showLatestNovels` marks the
"Latest" entry. Do not assume Latest removes filters; hosts can pass filter values or plugin defaults.
`options.filters` holds `{ type, value }` pairs keyed the same as your filter
definition.

### parseNovel

```ts
parseNovel(novelPath: string): Promise<Plugin.SourceNovel>
// NekoriPagePlugin: Promise<Plugin.SourceNovel & { totalPages: number }>
```

`novelPath` is the `path` from the `NovelItem` you returned, and the returned
`SourceNovel.path` should carry the same value.

### parsePage — `NekoriPagePlugin` only

```ts
parsePage(novelPath: string, page: string): Promise<Plugin.SourcePage>
```

Returns chapters of one numbered page.

### parseChapter

```ts
async parseChapter(chapterPath: string): Promise<Plugin.ChapterContent> {
  const html = await fetchText(this.site + chapterPath);
  return { state: 'ready', type: 'novel', html };
}
```

`ChapterContent` is the official object in Electron and Android; only `html` is rendered.
Required `type`: `novel | mixed | image | video`. All types still render HTML.

| Field | Meaning |
| --- | --- |
| `state: 'ready'` | Usable content. |
| `state: 'checkpoint'` | May render verification/login/locked-chapter HTML, but downloads and EPUB exports must fail. |
| `noCache?: boolean` | Prevent reader/runtime response reuse; does not itself prohibit downloads. |
| `noPrefetch?: boolean` | Stop read-ahead from this chapter and infinite append; does not itself prohibit downloads. |
| `checkpointMessage?: string` | Optional checkpoint explanation. |

A checkpoint declares both flags true; the normalizer forces them true as well.

```ts
return {
  state: 'checkpoint',
  type: 'novel',
  html: '<div id="captcha-placeholder">Please verify and reload.</div>',
  checkpointMessage: 'Verification required',
  noCache: true,
  noPrefetch: true,
};
```

Throw for failures without useful HTML. Checkpoints do not automatically solve CAPTCHA or retry;
customJS handles interaction and requests reload through the existing reader bridge.
LNReader strings are normalized upward; Nekori objects are not downgraded to strings or re-encoded as policy markers.

### searchNovels

```ts
searchNovels(searchTerm: string, pageNo: number): Promise<Plugin.NovelItem[]>
```

If the site's search has no pagination, `if (pageNo > 1) return [];`.

### resolveUrl — optional

```ts
resolveUrl(path: string, isNovel?: boolean): string
```

Maps an internal `path` back to a browsable URL, used by "Open in WebView".
Implement it when the site's URL layout differs from your `path` scheme.

## Filters

```ts
import { FilterTypes, Filters } from '@libs/filterInputs';
```

A filter definition object declares what appears in the app's filter sheet. Its
keys are how you read the values back.

```ts
filters = {
  genre: {
    type: FilterTypes.CheckboxGroup,
    label: 'Genres',
    value: [],
    options: [
      { label: 'Isekai', value: 'isekai' },
      { label: 'Romance', value: 'romance' },
    ],
  },
} satisfies Filters;
```

> Do not forget `satisfies Filters` — without it the value types in
> `popularNovels` are not inferred.

Every filter takes `label`, `type` and `value` (the default); the group types
also take `options`.

| `FilterTypes` | UI | `value` type |
| --- | --- | --- |
| `TextInput` | Free text field | `string` |
| `Picker` | Single choice | `string` |
| `Switch` | Toggle | `boolean` |
| `CheckboxGroup` | Multi-select | `string[]` |
| `ExcludableCheckboxGroup` | Tri-state multi-select | `{ include?: string[]; exclude?: string[] }` |

Reading values inside `popularNovels`:

```ts
options.filters.genre.value; // string[]
options.filters.genre.type;  // FilterTypes.CheckboxGroup

// ExcludableCheckboxGroup
const { include, exclude } = options.filters.tags.value;
```

## Plugin settings and storage

`pluginSettings` renders user-configurable options in the app's plugin settings
screen. Changes take effect after reloading the plugin/app.

```ts
pluginSettings: Plugin.PluginSettings = {
  hideLocked: { value: false, label: 'Hide locked chapters', type: 'Switch' },
  url:        { value: '',    label: 'URL' }, // type defaults to 'Text'
  quality: {
    value: '720',
    label: 'Quality',
    type: 'Select',
    options: [
      { label: '720p', value: '720' },
      { label: '1080p', value: '1080' },
    ],
  },
  hosts: {
    value: [],
    label: 'Hosts',
    type: 'CheckboxGroup',
    options: [{ label: 'Host A', value: 'a' }],
  },
};
```

| `type` | `value` type |
| --- | --- |
| `Text` (default) | `string` |
| `Switch` | `boolean` |
| `Select` | `string` + `options` |
| `CheckboxGroup` | `string[]` + `options` |

Values are read through `storage`, keyed by the setting name:

```ts
import { storage, localStorage, sessionStorage } from '@libs/storage';

const hideLocked = storage.get('hideLocked'); // boolean
storage.set('token', value, expiresMsOrDate); // expiry is optional
storage.delete('token');
storage.getAllKeys();
storage.clearAll();
```

`localStorage` and `sessionStorage` expose **`get()` only**: they are snapshots
of what the reader WebView wrote, handed to the plugin by the app. Set
`webStorageUtilized = true` to receive them. In the playground they are filled
from the preview tab (see [Testing](#testing)).

## Allowed imports

Current allowlist:

| Namespace | Exports / modules |
| --- | --- |
| `@libs/*` | `fetch`, `storage`, `filterInputs`, `novelStatus`, `defaultCover`, `isAbsoluteUrl` |
| `@libs/aes` | `gcm` |
| `@libs/utils` | `utf8ToBytes`, `bytesToUtf8` |
| `@nekori/plugin` | `NekoriBasePlugin`, `NekoriPagePlugin` |
| `@nekori/pluginMetadata` | `ContentType`, `ContentWarning` |
| `@nekori/aes` | `gcm`, `ctr`, `ecb`, `cbc`, `cfb` |
| `@nekori/utils` | `Buffer`, `NodeCrypto`, `getUserAgent`, `encodeHtmlEntities`, `decodeHtmlEntities` |
| `@nekori/cookie` | `set`, `get`, `setFromResponse`, `flush`, `removeSessionCookies` |

Also allowed: `@/types/plugin`, `cheerio`, `htmlparser2`, `dayjs`, `urlencode`, `node-html-markdown`.
Relative imports must stay inside the plugin folder.

The build embeds @nekori/plugin classes and metadata constants; other runtime APIs come from the host. @libs/cookie, @libs/pluginMetadata and @libs/webview are not current APIs.

@nekori/webview is a stub outside the plugin allowlist: solveCloudflare returns false, solveCloudflareTurnstile rejects. Neither is a working solver.

NodeCrypto uses Node in Electron and crypto-browserify on Android; use algorithms supported by both. cookie.flush() persists cookies.

- `fetchApi(url, init?)`: Response; check status before reading the body.
- `fetchText(url, init?, encoding?)`: decode text (UTF-8 default), returning an empty string on failure.
- `fetchProto<T>({ proto, requestType, requestData?, responseType }, url, init?)`: protobuf.

Bundles target ES2020. HBC is not implemented. Electron is for development; test releases on the app.

## Testing

> Custom JS (the `webview/` bundle) is **not** covered by Vite hot reload. Run
> `npm run build:assets` after each asset change. Rebuild plugin bundles when
> metadata changes.

Build and type-check are separate. Use `npm run type-check` for all scopes, or
`npm run type-check:plugins` / `npm run type-check:webviews` while iterating.

`npm run build:prepare` runs the clean multisrc, multisrc generation, plugin
bundle, and asset steps. `npm run build:full` adds the manifest. `npm run dev`
uses the preparation pipeline before starting Electron; `npm run serve:dev`
prepares the repository before its development manifest.

After `npm run build:full`, run `npm run test:build` to validate the emitted
plugin assets. `build:assets` must follow `build:plugins` because it reads the
compiled plugin metadata.

Run `npm run test:checks` for the localhost site-probe and plugin validation
regressions, including valid, empty, and malformed M3U responses.

### Automated checks

`npm run check:sites` checks each unique `plugin.site` from local compiled
metadata through Electron/Chromium with a bounded GET request, follows
redirects, retries transient failures, and writes `broken-sites-report.json`.
Secure Cloudflare DoH and opportunistic ECH are enabled by default when the
server publishes the required HTTPS/SVCB records. Use
`--dns-mode secure|automatic|off`, `--doh HTTPS_URL`, or `--no-ech` to tune the
path. `--no-ech` disables Chromium's `UseDnsHttpsSvcb` HTTPS/SVCB discovery and
ECH hints; it does not disable DoH. A live Chromium 150 check negotiated TLS
1.3 with encrypted SNI by default and plaintext SNI with `--no-ech`. Flags also
include `--plugin ID`, `--url URL`, `--timeout MS`,
`--attempts N`, `--concurrency N`, and `--output FILE`. Each report entry keeps
the plugin list for duplicate sites, input/final URL, every redirect hop,
host transitions, status, attempt count, and reason. The check reports what it
reached and does not edit plugin metadata. Statuses are `accessible`, `blocked`,
`http_error`, `network_error`, `timeout`, and `invalid_url`. Blocked means the
site responded but content could not be verified, so it exits 0; the other
non-healthy statuses exit 1.

`npm run check:plugins` runs sampled real plugin methods in hidden Electron
windows with a fresh isolated profile and settings store. It accepts repeated
`--plugin ID`, `--query TEXT`, `--novel PATH`, `--chapter PATH`, `--config FILE`,
`--timeout MS`, `--output FILE`, `--list`, `--dns-mode secure|automatic|off`,
`--doh HTTPS_URL`, and `--no-ech`. Use `--method NAME` with
`--args JSON` or `--args-file FILE` to invoke exactly one method; the report
uses `mode: "single_method"` and includes bounded/redacted argument and result
previews, request timing, and a sanitized stack. `--debug` adds verbose smoke
diagnostics. `--inspect` is restricted to one plugin and method, opens visible
DevTools, pauses before invocation, and keeps the window until it is closed.
A config is keyed by plugin ID:

```json
{"plugin.id":{"settings":{},"query":"...","novel":"...","chapter":"..."}}
```

On Windows, prefer an args file to avoid shell quoting:

```json
["/novel/example"]
```

```powershell
npm run check:plugins -- --plugin example --method parseNovel --args-file .\args.json --inspect
```

The smoke path validates returned entities and follows available data through
popular/search, novel, page, chapter, and URL resolution methods. Required empty
or skipped methods fail the run; optional methods may be skipped. CAPTCHA and
interactive challenges are not solved. These checks sample behavior and do not
prove complete catalog correctness or full Hermes/device compatibility. Method
statuses include `passed`, `failed`, `empty`, `blocked`, `skipped`, and `timeout`;
request correlation can also report `network_error`. A
fully passed run exits 0; failed, empty, blocked, timeout, network, or required
skipped results exit 1.

### Electron playground

```bash
npm run dev
```

The only interactive way to test — there is no browser mode. It is not bound by
CORS, keeps persistent cookies, and runs the copied reader runtime with an Electron host adapter.

- **Spawn New Tab** (`Ctrl+T` / `Cmd+T`) opens a WebView where you can solve
  Cloudflare/Captcha by hand; the cookies are synced to plugin `fetch` calls.
- **Open Preview** in *Parse Chapter* opens the chapter in its own Electron tab
  with the base URL set to `plugin.site`, so relative URLs resolve and
  `customCSS` / `customJS` run the way they do in the reader. The inline panel
  always shows raw HTML.
- Whatever the preview tab's custom JS writes to `localStorage` /
  `sessionStorage` is mirrored back, which is what makes `@libs/storage`'s
  `localStorage.get()` / `sessionStorage.get()` return data in the playground.
- DevTools: `F12` in the preview tab, or the debug icon in the WebView tab.

## Custom CSS and JS

`customJS` is bundled from `webview/index.ts` or `index.js`; `customCSS` is copied from `webview/style.css`. Rebuild assets after edits. A bare metadata filename is published under `public/static/src/<plugin.id>/`.

The Electron dev client uses a checked-in copy of Nekori's built reader in `public/static/novel-reader/`, including declarations, CSS, VanJS widgets and offline media engines. There is no reader npm dependency or sibling-checkout requirement for normal builds. To refresh the snapshot, run these commands **in Nekori's app/tools/reader-runtime**, then commit the copied files in the plugin repository:

```sh
npm run build
node sync-dev-client.mjs /path/to/nekori-plugins
```

In the plugin repository, `npm run build:reader` builds the Electron adapter from those local files. `build:prepare` includes it. Open Preview runs this real runtime; F12 opens its DevTools. Native Android synthesis, AI services, downloads and chapter navigation are host responsibilities and are not implemented by this standalone preview.

| Path | Purpose |
| --- | --- |
| `public/static/novel-reader/` | Copied app `dist`: runtime, assets, styles, declarations and media vendors. Commit these files. |
| `src/lib/reader-client.ts` | Electron host adapter. |

### Reader API

CustomJS runs in WebView, separately from the source plugin's Hermes runtime.
Use the lowercase global `window.nekori`; `@libs/*` helpers are not injected into this document.
`src/types/webview/index.d.ts` imports the copied app declarations.
If you need named types from `plugins/<language>/<PluginName>/webview/index.ts`, use a type-only import:

```ts
import type { ReaderApi, DashConfig } from '../../../../public/static/novel-reader/index.js';
```

The runtime publishes the global before its controllers finish initializing.
Wait for `ready`, and use an async function instead of top-level await because customJS is bundled as a classic IIFE:

```ts
void (async () => {
  const reader = window.nekori;
  if (!reader) throw new Error('Reader is unavailable');
  await reader.ready;
  console.info(reader.context.chapter.id, reader.context.chapter.path);
})().catch(error => window.nekori?.error(String(error)));
```

| Member | Contract |
| --- | --- |
| `ready` | `Promise<void>`; runtime controllers are initialized, not necessarily fonts/images/page reflow/media playback. |
| `context` | Live getters for document/novel/chapter/runtime/configuration data, detailed below. |
| `config` | Current `ReaderConfig`; app-owned configuration, not a native preference setter. |
| `events.subscribe(name, listener)` | Returns an unsubscribe function. The supported state notification is detailed below. There is no public `emit`. |
| `layout` | `ReaderLayout` or `null`; check `enabled` before paged operations and allow `position` to be `null`. |
| `player` | `ReaderPlayer` or `null`; ordinary text documents have no media delegate. |
| `fetch(input, init?)` | `Promise<Response>`; host proxy using standard RequestInit and forwarded headers. Check `response.ok` yourself. |
| `refetch()` | `void`; asks the host to reload from the source. It is not a completion promise. |
| `error(message)` | `void`; reports a string to the host reader error channel. |
| `dispose()` | `void`; tears down the document, owned by the embedding application. Do not use it as a source-UI cleanup helper. |

#### Context, metadata and runtime

`context` exposes `documentId`, `mode` (`reader`, `download`, `error`), `novel`, `chapter`, `nextChapter`, `chapters`, `runtime`, and `strings`.
Optional configuration fields are `ui`, `style`, `layout`, and `player`; these are data, not the controllers at `reader.layout` / `reader.player`.
Optional identity fields are `sourceBaseUrl`, `sourceId`, `novelId`, and `chapterId`; novel/chapter IDs default to the corresponding metadata IDs.

| Object | Fields |
| --- | --- |
| `novel` | String `id`, `name`, `path`. |
| `chapter`, `nextChapter` | String `id`, `name`, `path`; numeric `progress`; optional string `url` and numeric `number`. `nextChapter` can be null. |
| `chapters` | Metadata supplied to this document; the Android reader supplies loaded chapters, not the full source catalog or chapter bodies. |
| `runtime` | Boolean `editing`, `infinite`, `textSelectionBlocked`, `forcedLowercase`, `menuVisible`, `immersive`, `loadingChapter`, `loadingNext`, `noMoreChapters`; `ttsState` is `playing`, `paused`, `stopped`, or `starting`. |

Native database IDs are decimal strings; do not convert them to Number.
`path` is an opaque source identity, not an external URL to normalize or concatenate blindly.
`chapter.progress` is host-supplied saved progress, not a live DOM scroll tracker.
`runtime` does not expose progress/chapterProgress/currentChapterId.
Read fresh context fields when needed; mutating these objects does not navigate, save library data, or change native preferences.

#### State subscriptions

`document.stateChanged` receives `{ runtime, event? }` after a host config/runtime patch, without a DOM Event/detail wrapper.
Read the initial state before subscribing; the optional event string is a host label.
On custom UI teardown, unsubscribe the listener:

```ts
const reader = window.nekori;
if (reader) {
  console.info(reader.context.runtime.ttsState);
  const unsubscribe = reader.events.subscribe('document.stateChanged', ({ runtime }) => {
    console.info(runtime.ttsState);
  });
  // Call unsubscribe() when removing the custom UI that owns this listener.
}
```

`layout.positionChanged`, `chapter.appended`, `reader.error`, and other reader-to-native protocol events are not automatically echoed to subscriptions.
The old `tsundoku:*` DOM events are not dispatched.
There are no public next/previous/TTS/translation actions or private-bridge access methods on ReaderApi.

#### Layout and source DOM

Paged operations return booleans: `moveBy(delta, behavior?)`, `seekUnit(index, behavior?)`, `seekPercent(percent)`, `revealElement(element)`, and `reflow(preserveViewport?)`.
Use -1/+1 for a reading-unit turn; moving forward at the loaded boundary can request another chapter.
`seekUnit` is zero-based within the visible chapter; `seekPercent(50)` seeks halfway.
`layout.position` has `chapterId`, `unitIndex`, `unitCount`, `firstPage`, `lastPage`, `totalPages`, and `progress` (0–1).
A unit can be a single page or a two-page spread; wait for a non-null position when reading it.
Use revealElement instead of scrollIntoView in paged mode.
Leave `configure`, `prepareSilentTurn`, `finishSilentTurn`, and controller `dispose` to the embedding app.

The root is `#nekori-reader` / `.nekori-reader` / `[data-nekori-reader-root]`.
Chapters use `<nekori-chapter class="nekori-chapter">` with `data-nekori-chapter-id`, `-name`, `-number`, `-path`, and `-url` attributes across scrolling and paged layouts.
Plain text uses `.nekori-plain-text` / `[data-nekori-plain-text="1"]`.
Scope source CSS to chapter/plugin-owned elements and preserve the app's root/wrappers.
Summary/feedback internals are in shadow roots; ordinary chapter selectors do not style them.

Use `--reader-background-color`, `--reader-text-color`, the `--reader-*` typography/margin settings and `--md-sys-color-*` theme colors.
There is no JavaScript theme object; read values with `getComputedStyle(document.documentElement).getPropertyValue(name)`.

Enabled source customJS included in the document runs once after reader initialization.
Only user snippets opted into append handling are rerun by native on infinite-scroll appends; source customJS is not automatically rerun.
Use a scoped MutationObserver if your source UI needs to respond to added chapter nodes.
Inline scripts in returned HTML are subject to the embedded-JS setting and content processing; keep source behavior in customJS.

#### Fetch and refetch

Use reader.fetch for HTTP(S) URLs when the reader proxy is enabled.
It accepts a URL string, URL object or Request; relative strings must be resolved against a real source URL before proxying.
Use native browser fetch for blob/data URLs.
When the proxy is disabled, reader.fetch reports an actionable host error and rejects.

After successful verification, call reader.refetch(): the Android host reloads the current chapter from source; Electron syncs web storage and reruns parseChapter for the preview path.
The operation creates another document, so do not retain the old API/DOM references.
Reader globals such as `reader`, `tts`, `pageReader`, `van`, `LNReaderPlayer`, `ReactNativeWebView`, `Tsundoku`, and `TsundokuTheme` are not supplied.

## Video plugins

Return structured content with `type: 'video'`, `noCache: true`, `noPrefetch: true`. Nekori's player uses Video.js with hls.js/dash.js. New plugins use `nekori-*` metadata:

```ts
return {
  state: 'ready', type: 'video', noCache: true, noPrefetch: true,
  html: [
    '<meta name="nekori-video-mode" content="direct">',
    '<meta name="nekori-video-type" content="m3u8">',
    '<meta name="nekori-video-url" content="https://example.com/video.m3u8">',
  ].join('\n'),
};
```

Direct mode starts automatically. Accepted types are `m3u8` (HLS/MSE), `mpd` (DASH), `video-file` and `iframe`. There are no hls/dash aliases. Iframe URLs must be HTTP(S) and cannot be downloaded.

For URLs resolved by source customJS, set `nekori-video-mode` to `lazy`, await reader.ready, then call the player. Play methods return `Promise<void>`; await initialization and catch unexpected rejections. Playback/engine failures are also reported to the host; a resolved promise does not guarantee playback:

```ts
const reader = window.nekori;
if (!reader) throw new Error('Reader is unavailable');
void reader.ready.then(async () => {
  if (!reader.player) throw new Error('This chapter has no player');
  await reader.player.playHls('https://example.com/video.m3u8', { /* standard hls.js configuration */ });
}).catch(error => reader.error(String(error)));
```

### Player API

| Method | Arguments |
| --- | --- |
| `playHls(url, config?)` | Standard hls.js configuration, including custom loaders. |
| `playDash(url, config?)` | `{ settings?, protectionData? }`; standard dash.js objects. |
| `playDirect(url)` | Direct video file. |
| `playIframe(url)` | Embedded player. |
| `log(message)` | Console log; also appends to the player overlay when debug is enabled. |
| `setDebug(enabled)`, `toggleDebug()` | Player debug overlay. |
| `addSubtitles(trackOrTracks)` | `Promise<void>`; one track or an array. Fields: label?, lang?, url?, content?, default?. Supply content or a URL. |
| `dispose()` | Document lifecycle cleanup, normally owned by the reader. |

Engine instances and player DOM internals are private. Pass engine settings through playHls/playDash instead of accessing hlsInstance/dashInstance.

```ts
// Replace these URLs/headers with values resolved by your source.
void (async () => {
  const reader = window.nekori;
  if (!reader) throw new Error('Reader is unavailable');
  await reader.ready;
  const player = reader.player;
  if (!player) throw new Error('This chapter has no player');
  await player.playDash('https://example.com/manifest.mpd', {
    settings: { streaming: { buffer: { bufferTimeAtTopQuality: 30 } } },
    protectionData: {
      'com.widevine.alpha': {
        serverURL: 'https://example.com/license',
        httpRequestHeaders: { Authorization: 'Bearer YOUR_TOKEN' },
      },
    },
  });
  await player.addSubtitles({
    label: 'English', lang: 'en',
    url: 'https://example.com/subtitles.vtt', default: true,
  });
})().catch(error => window.nekori?.error(String(error)));
```

dash.js settings are replaced, not merged. Do not default a DRM robustness level: the Android WebView may reject a stricter value. Protected playback follows host permission and incognito policy; Electron DRM capability does not prove Android DRM compatibility. Subtitle content supports WebVTT and SubRip conversion; other formats must be converted by the plugin. External subtitles are not included in downloaded video files.

Subtitles can be prepared before play or added afterward; prepared tracks survive player remounts. A failed track is logged and skipped rather than rejecting the entire addSubtitles operation.

## Special meta tags

| Metadata | Meaning |
| --- | --- |
| `meta[name=nekori-video-mode]` | direct or lazy. |
| `meta[name=nekori-video-type]` | m3u8, mpd, video-file, iframe. |
| `meta[name=nekori-video-url]` | Direct playback URL; escape HTML attribute values. |
| `meta#nekori-video-disable-progress` | Disable progress/live-style playback; not downloadable. |
| `meta[name=nekori-video-poster]` | Poster image. |
| `meta[name=nekori-video-thumbnails]` | WebVTT thumbnail storyboard. Opt-in forces anonymous CORS on the media element. |
| `meta[name=nekori-debug-mode]` | true enables the debug overlay. |

The chapter's state/type/cache/prefetch policy belongs in ChapterContent, not legacy control markers. Old offline marker decoding is an app load-boundary concern.

## Captcha and blocked sites

Return a checkpoint with interaction HTML and noCache/noPrefetch true. Source customJS performs verification, then calls window.nekori.refetch(). Electron syncs preview web storage before requesting the fresh chapter. Checkpoints cannot be treated as successful downloads or prefetched completed chapters. No automatic solver or general plugin–customJS IPC is implied by this API.
